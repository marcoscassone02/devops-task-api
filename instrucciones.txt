# Guía rápida de DevOps Task API

Comandos y conceptos esenciales. Ejecutar desde la raíz del repositorio.

## Arquitectura

```text
GitHub Actions -> calidad y seguridad -> imagen en GHCR
                                           |
                                           v
EC2 -> Docker Compose -> FastAPI + Alembic + PostgreSQL
                                           |
                                           v
                              EBS persistente /data/postgres
```

- `compose.yaml`: desarrollo local; construye las imágenes.
- `compose.deploy.yaml`: override de EC2; descarga la imagen de GHCR y monta el
  EBS en PostgreSQL.
- La EC2 tiene un EBS raíz reemplazable y otro EBS persistente para PostgreSQL.
- Parameter Store guarda la contraseña cifrada.
- Session Manager permite administrar EC2 sin abrir SSH.
- `user-data.sh.tftpl` pasa valores de Terraform a `bootstrap.sh`.
- `bootstrap.sh` prepara una EC2 nueva, monta EBS y levanta los contenedores.

## Docker local

```bash
cp .env.example .env
docker compose up --build --detach
docker compose ps --all
docker compose logs --follow
curl http://localhost:8000/health
docker compose down
```

Eliminar también la base local, únicamente si se quiere perder esos datos:

```bash
docker compose down --volumes
```

## Tests y seguridad

```bash
docker compose run --rm --build test

docker build --target test --tag devops-task-api:test .
docker run --rm devops-task-api:test ruff check .
docker run --rm devops-task-api:test pip-audit --requirement requirements.txt
```

- Ruff revisa estilo y errores estáticos.
- pytest ejecuta los tests con SQLite en memoria.
- pip-audit revisa vulnerabilidades de dependencias Python.
- Trivy revisa la imagen runtime dentro de GitHub Actions.

## Alembic

Crear una migración después de modificar los modelos:

```bash
docker compose run --rm migrate \
  alembic revision --autogenerate -m "descripcion"
```

Revisarla y aplicarla:

```bash
docker compose run --rm migrate
docker compose run --rm migrate alembic current
```

`stamp head` solo registra una base preexistente cuyo esquema ya coincide:

```bash
docker compose run --rm migrate alembic stamp head
```

## Git y GitHub

```bash
git switch main
git pull --ff-only
git switch -c tipo/descripcion

git status
git diff
git add ARCHIVOS
git commit -m "descripcion"
git push -u origin tipo/descripcion
gh pr create --base main --head tipo/descripcion
```

Después de fusionar:

```bash
git switch main
git pull --ff-only
git push origin --delete tipo/descripcion
git branch -d tipo/descripcion
```

Los pull requests ejecutan calidad y seguridad. Un push a `main` también
publica `latest` y el SHA del commit en GHCR.

```bash
docker pull ghcr.io/marcoscassone02/devops-task-api:latest
```

## Terraform y AWS

Renovar la sesión cuando expiren las credenciales:

```bash
aws login --profile devops-task-api
```

Flujo habitual:

```bash
AWS_PROFILE=devops-task-api terraform -chdir=infra/terraform init
AWS_PROFILE=devops-task-api terraform -chdir=infra/terraform fmt -check -recursive
AWS_PROFILE=devops-task-api terraform -chdir=infra/terraform validate
AWS_PROFILE=devops-task-api terraform -chdir=infra/terraform plan -out=plan.tfplan
AWS_PROFILE=devops-task-api terraform -chdir=infra/terraform apply plan.tfplan
AWS_PROFILE=devops-task-api terraform -chdir=infra/terraform output
```

- `resource`: recurso que Terraform administra.
- `data`: consulta información existente.
- `variable`: dato configurable.
- `output`: dato útil resultante.
- `templatefile`: renderiza un archivo insertando valores de Terraform.
- `plan`: vista previa; no cambia AWS.
- `apply`: ejecuta el plan.
- El estado remoto vive cifrado y versionado en S3.

Antes de reemplazar EC2 o tocar almacenamiento, revisar que el plan no destruya
el EBS de PostgreSQL ni el parámetro secreto. Crear un snapshot cuando exista
riesgo para los datos.

## EC2 y despliegue

Conectarse sin SSH:

```bash
INSTANCE_ID="$(AWS_PROFILE=devops-task-api \
  terraform -chdir=infra/terraform output -raw api_instance_id)"

AWS_PROFILE=devops-task-api aws ssm start-session \
  --target "${INSTANCE_ID}" \
  --region us-east-1
```

Comprobar la máquina:

```bash
sudo cloud-init status --wait
findmnt /data/postgres
sudo docker compose \
  -p devops-task-api \
  -f /opt/devops-task-api/compose.yaml \
  -f /opt/devops-task-api/compose.deploy.yaml \
  ps
curl -fsS http://localhost:8000/health
curl -fsS http://localhost:8000/tasks
```

Logs:

```bash
sudo docker compose \
  -p devops-task-api \
  -f /opt/devops-task-api/compose.yaml \
  -f /opt/devops-task-api/compose.deploy.yaml \
  logs --tail=100 api db migrate
```

## Recordatorios

- No confirmar `.env`, `*.tfvars`, estados ni planes de Terraform.
- No ejecutar `mkfs` sobre un volumen con datos.
- Eliminar una EC2 no elimina el EBS persistente del proyecto.
- El EBS raíz sí se elimina con la instancia.
- Los snapshots, volúmenes, EC2 y direcciones IPv4 públicas generan costos.
- `migrate` en estado `Exited (0)` es normal: termina después de migrar.
